# Evaluation versioning

The owner authorized commits and GitHub pushes on 2026-11-08. These deterministic
interpreter iterations are evaluations/development, not statistical weight training.

Git stores synthetic sources/exports, manifests, semantic adjudications,
code/tests, small summaries, gate logs and reports. Large per-question execution
results/predictions are excluded: they duplicate generated output and can contain
national-derived record samples. Do not commit snapshots or source ZIPs.

Full existing evidence remains in local result paths in COMMANDS.md.
evidence-sha256.json pins raw outputs even when not in Git. A hash identifies an
artifact but is not a download. Missing outputs require documented commands and
local data; old baselines can require the recorded historical executable/source.
Do not claim a complete portable archive without an artifact destination/access
policy. Never fabricate missing raw evidence.

Future stages should commit authoring tools/seeds and source registries, reviewed
batches, isolated fixes with required fixtures/tests, and measured reports.
Version adjudications separately from frozen inputs. Run the project gate before
implementation commits. Leave unrelated workspace files out.

## Still open (not fixed here), by priority

### P1 — blocks the WP-5.1 decision or can produce a wrong number

1. **WP-3.3 evaluation sets must be rebuilt** by people, not scripted: remove clones and
   index-based noise labels, use core sector sets, make homonyms without UF clarify, add
   the claimed minimal pairs, make `dialogues.jsonl` evaluable (`missing field gold`),
   move them off `IbgeEstimate(2025)` (they and `eval.rs` still use it). Banner added to
   `2026-11-06-eval-sets.md`.
2. **Owner confirmation** of the 50 H-dev labels and the 50 priority sectors. The
   catalogue needs changes a reviewer would ask for: `transport` core includes parking
   (5223100) and postal services (5310501/02); `beauty_salon` lacks 9602502;
   `building_materials` leaves 4744005 out of core; curated aliases are missing for
   barbearia, mercado, imobiliária, escola, construção/construção civil, contabilidade,
   advocacia, TI/tecnologia da informação, transporte de carga/passageiros.
3. **Density denominators ignore place and population filters** (`execute.rs`
   `member_population_for`): with `place_population` or `Near`, the numerator is filtered
   and the UF/region population is not.
4. **Engine lowering drops an empty resolved place set** (`lab/src/query.rs`): e.g.
   Region(Nordeste) with `within_ufs=[SP]` counts nationwide on the engine.
5. **Aggregate artifacts are not fully checked at open**: required tables (a current
   artifact built with `--tables T1,T2` makes flows silently 0) and the municipality
   catalogue SHA-256 against the catalogue in use.
6. **Canonicalization gaps**: a UF both in the place filter and excluded is kept (golden
   case `exclusions`); `validate()` accepts non-canonical requests (sector ids and CNAE
   sets that disagree). Suggest a `CanonicalRequest` input type.
7. **The differential oracle is not independent** for place resolution, population and
   CNAE sections (it shares the executor's code), past competences are never cross-checked,
   and `diff-agg` skips the UfCnae marginals and T5.

### P2 — quality and maintainability

8. Python is required to rebuild the CNAE catalogue (`scripts/build-cnae.py`) and the
   frozen sets (`eval/build-sets.py`); the plan puts builders in `opencnpj-lab` (Rust).
9. `h-dev.jsonl` is not in Git (`tests/h_dev.rs` is ignored); commit it after the owner
   review.
10. Evaluation metrics: exact match compares raw JSON instead of canonical IR; equal
    confidences are not grouped on the risk–coverage curve; AURC normalization; entity
    P/R without spans.
11. Synthetic generator: abbreviation step replaces substrings ("separa" → "sep/"),
    phonetic step doubles every "s", typos may hit digits while the gold is unchanged,
    template `t{place.prep}`, coverage levels take the first N % of the catalogue (only the
    North at L1) instead of stratified sampling; the 200-item naturalness review is pending.
12. `scripts/vps-emulate.sh` reruns under `sudo` on any failure (including the benchmark's
    own failure or an OOM kill) and does not record which mode ran.
13. Renderer: the template lint uses one global placeholder schema (missing values now
    fail at render time, which the golden test exercises, but a per-key schema would catch
    it statically); `supported_keys` is hand-maintained; `Sources` cites the current
    snapshot SHA-256 even for a past competence; region labels need catalogue wiring;
    UF subjects without article ("Paraná tem").
14. **Phase 4 has not started**: `opencnpj-nlu` is still empty. The language understanding
    — the core of the product — is the next work, after P1 items 1–2.
